## What the gate is

M7 reuses the complete M0–M6 engineering chain (M0 inventory on the exact
104‑group / 593‑subtest plan, build/vet/module-verify, m0–m7 Python
regressions, unit + real-service integration suites, the M1 real-process E2E,
sqlc v1.31.1 pinning, Linux `-race`) plus the M6 release acceptance
(manifest, five executable drills, per-profile index), and adds the fail-closed
realtime layer:

- recorded preparation before the unit suite: dedicated realtime database
  (`m5_template_m7rt_*`) inside the isolated project's pinned PostgreSQL,
  `-cover`-instrumented `examples/realtime` demo binary (with `-race` on the
  Linux child), `--provision` schema/credentials, and an exact fixture-CLI
  deletion of the unused default stream;
- official `@microsoft/signalr` 10.0.0 harness: three release profiles, two
  independent instrumented nodes on real PostgreSQL/NATS, every child counter
  joining the raw atomic coverage union;
- official-client dependency/license lock (18 packages; MIT/BSD/Unlicense)
  re-derived against `deploy/release/m7-client-dependencies.json`;
- release coverage ≥90% raw statement coverage overall and for every critical
  package (adds `modules/realtime/...` and `events/nats`);
- additive release manifest `deploy/release/m7.json` — 104 requirements
  (95 historical + RT-001..RT-009), 593 named subtests; VERSION stays `0.1.0`
  (the realtime subsystem targets v0.2, not a tag release);
- per-profile evidence index `profile-evidence-m7.json` (593 × 3 rows, every
  required row bound to its exact raw artifact sha256).

## Gate reproducibility (read-only validation)

- `release-m7.json` is derived purely from the raw artifacts and written once
  with canonical LF bytes by the verify hook; gate-time validation
  (`scripts/m7.py validate_stored_release_m7`) only loads the stored bytes,
  re-derives the evidence and fails closed on stored-JSON drift or any
  mismatch between the recorded artifact hash and the on-disk bytes. Neither
  validation nor gate commands rewrite, re-emit or re-time evidence.
- After `scripts/m7.py gate --commit 42c2622c270d1389b9d4775abb1d584cdf75a9ad`
  every raw artifact and command-log hash was recomputed independently from
  disk against both platform reports — zero mismatches; the full
  bytes-plus-mtime snapshot before/after the gate differs only by `gate.json`
  itself, and a second gate run left every evidence file bit-identical
  (gate.json content identical as well).
- Historical record: the same-day first gate attempt at source
  `1d7a8ce75c9142eee4a31952bf7160568949f198` was rejected and is **not
  Verified** — its `validate_report` rewrote the release artifact with the
  host's default newlines and compared parsed JSON, a tautology that silently
  broke the Linux artifact hash. The fix is the read-only validation above;
  the Linux `release-m7.json` of that attempt was restored to its LF bytes
  matching its own recorded hash, and that attempt's reports stay in place as
  a record only.

## Limitations

- The five release drills ran once on Windows for this source and were adopted
  by the Linux runner (no Docker socket); their provenance is in the drill
  report.
- Race evidence is recorded at per-case level: the Linux full `-race` run's
  raw Go JSONL `41-race.log` (under `m7/linux-amd64/`) enumerates every named
  test and reports 1391 named passes, zero named fail and zero named skip.
  Package entries without an individual test name in that JSONL are package
  start/done records, not skipped acceptance cases.
- The realtime demo fixture key is loopback-only; no production credentials
  exist in evidence.
- Raw coverage differs by one covered `modules/realtime/signalr` statement
  between the earlier 1d7a8ce attempt reports (7963/7966, signalr 283/298)
  and this verified run (7962/7965, signalr 282/298); the union is rebuilt
  per run, thresholds are unchanged and no evidence here depends on the
  superseded attempt.
- Historical M0–M6 verdicts are unchanged; M7 is additive. No release tag, no
  push and no deployment were performed; product VERSION stays 0.1.0 and the
  realtime subsystem targets v0.2.
