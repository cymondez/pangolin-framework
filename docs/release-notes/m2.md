# 0.1.0 開發期間：M2 API 與 schema 變更

M1–M6 產品版本維持 0.1.0。既有 `Within`／`Current`、Options／Scope／Completion 簽章不變；M1 的明確拒絕項目 RequiresNew、RepeatableRead／Serializable 現由選項矩陣實作。無 Savepoint／Suppress、非交易寫入或跨 DB 原子保證。

UOW 錯誤名稱依規範統一為 `UOW_REQUIRED`／`UOW_CLOSED`／`UOW_BUSY` 等，提供 errors.Is sentinel 與 errors.As Error。從 M1 的 `UOW_SCOPE_REQUIRED`／`UOW_SCOPE_ENDED`／`UOW_CONCURRENT_USE` 遷移時更新比較值。已確認成功後的回呼錯誤只記錄、不讓 Within 返回業務失敗；可靠工作繼續使用 Outbox。

Resource 可明示 DatabaseKey／RequiresTransaction；未明示者維持 transactional 預設，未明示 key 時每個 Manager 使用獨立身分。需要跨 Manager 共用同一資源時必須明示相同 key。PostgreSQL 預設以 Pool 身分為 key，可透過 Resource.Key 明示；不相容 Required 會使根 rollback-only。Transaction 可提供 Flush／BeforeCommit／Prepare／Release 與 CommitFailureOutcome，完成流程由 Manager 擁有，不暴露給業務。

PostgreSQL Query 現支援 Rows；Repository 需關閉並檢查 Err，QueryRow 必須 Scan。任何重疊操作或捕捉的 SQL 錯誤仍使根 rollback-only。Rows.Conn 返回 nil，避免經 cursor 取得底層連線。QueryRow／Query 的寫入 RETURNING 必須以 `Current(work,true)` 取得 Executor。

新增共用 Application Command／Query 與 transaction-aware HTTP Command／StreamOperation；HTTP Command 必須是頂層，拒絕加入外層 UOW。TenantScopeProvider 的 Authorize 預設拒絕，需明示 Permission checker；選取資格不等於業務權限。

Bookstore 新增 VersionedRepository、Update／Delete 的 expected-version 條件與 soft delete。tenant-only fixture books 新增 nullable `deleted_at`，app role 需 UPDATE 權限，Get 加入 `deleted_at IS NULL`。新 schema 的 tenant policies 同時比對 tenant Kind／ID。開發中 disposable 環境優先清除自己的 volumes 後重建；正式資料升級必須走 M3 部署 migration／相容性閘門，不能由 API 自動改表。

組織範例使用獨立 `ScopedRepository`／`NewScopedBooks` 與選用的 scoped-schema.sql，不能把原 tenant Repository 直接拿給 Org 使用。中立 catalog 與完整 owner 複合 FK／RLS 保持獨立於 organization 私有表；完整治理與配送仍依 M3 交付。

Bookstore 的不支援 Scope Kind hint 由原薄片的 403 對齊為 400／SCOPE_KIND_UNSUPPORTED；Tenant／Scope ID 偽造仍拒絕。Unknown 回覆新增 operationId 與 outcome，既有客戶端應以明確錯誤碼處理。
