# panGOlin-framework 0.1.0 發布說明

產品版本 0.1.0（[VERSION](../../VERSION)），規範基線 v1.3，範圍以[實作規範 §15](../../design/panGOlin-framework_實作規範書.md#s-15)為唯一依據。本說明隨同 commit 的發布 manifest、五項發布演練證據與雙平台 Gate 交付；文件本身不構成通過證據，完成狀態以同 commit 的 Gate 判定為準。

## 安裝與快速開始

- **Go Module**：`go get github.com/pangolin-framework/pangolin@v0.1.0`
- **pangolin CLI**：`go install github.com/pangolin-framework/pangolin/cmd/pangolin@v0.1.0`（或由 [GitHub Releases](https://github.com/pangolin-framework/pangolin/releases/tag/v0.1.0) 下載對應平台執行檔）
- **官方文件網站**：[https://pangolin-framework.github.io/pangolin/](https://pangolin-framework.github.io/pangolin/)

## 最低需求

Go 1.27.4、PostgreSQL 18.7、NATS JetStream 2.15.3；部署工具鏈固定 Goose 3.30.0 與 sqlc 1.31.1（[deploy/toolchain.json](../../deploy/toolchain.json)）。支援 linux/amd64 與 windows/amd64。API／Worker 程序使用非 root、無 BYPASSRLS 的最小權限資料庫角色；Secrets 由環境或密鑰服務注入。

## 首版交付範圍

- **Kernel／模組系統**：編譯期模組註冊、DAG 驗證、跨模組 lifecycle、明確 Provider 註冊與四層唯讀組態；啟動失敗回收資源、正常停機 Drain。
- **工作單元與資料存取**：完整 `UnitOfWorkManager.Within` 契約（Required／RequiresNew、唯讀／可寫、完成回呼、Commit Unknown 語意）；PostgreSQL pgx Adapter、單一部署用 Migration 工具與全域鎖；中立 `persistence/database` Port 與 MySQL／SQLite Adapter。
- **身分與隔離**：RS256 JWT／JWKS 驗證、可擴充 Authentication pipeline、Permission 預設拒絕、Tenant 與中立 Scope 隔離、FORCE RLS、必要 Audit 與獨立安全日誌。
- **可選 organization 模組**：Enterprise／Organization／Membership 與治理、中立 resource_scopes catalog、兩種 Bookstore Profile 與替換契約。
- **可靠事件與工作**：Local Event、Outbox／Inbox（真實 JetStream Broker）、冪等 Command、單次／重試 Jobs（lease 欄柵、dead-letter、容量 admission）。
- **平台服務與 CLI**：Memory Cache、分層 Settings（5–7 層）、Features、Logs／Metrics／Tracing／Health；`pangolin` CLI 與兩種 Profile 範本（同版受管 Runtime 內嵌）、`--realtime` SignalR 即時通訊可選模組、OpenAPI、Quickstart。
- **Bookstore 範例**：完整分層示範（`examples/bookstore`），作為範本與驗收的對照實作。

## 破壞性變更與相容性

0.1.0 是首個正式範圍版本；開發期間的 API 調整已依里程碑記錄於各[變更說明](.)：UOW 完成契約與錯誤碼（m2）、治理與可靠事件（m3）、Jobs／觀測（m4）、Settings 分層、中立資料存取與 Authentication pipeline（m5）。已發布的 Event Schema（`bookstore.book_created` v1）不可無通知破壞；後續版本須走版本化契約與 Upcaster。CLI 範本內嵌的 0.1.0 Runtime 原始碼帶 checksum manifest（`runtime-manifest.json`）並由 `pangolin upgrade` 管理升級，確保可重現的離線建置與完整性驗證。

## 風險與已知界線

- 事件配送為 **at-least-once**；外部副作用（付款、郵件等）必須使用穩定冪等鍵或由本地 Outbox 派送，不宣稱端到端 exactly-once。
- Memory Cache／Settings 無跨程序共享或 DB 原子交易；需要跨程序可靠通知時注入 Publisher／Outbox。
- `pangolin_security.tenant_memberships` 為權威中繼資料，不含業務內容，無 RLS（供 trusted tenant authority 讀取）；細節與剩餘風險見[安全審查](../security/release-review.md)。
- 效能基線只描述量測當下的硬體、負載與方法（p95／p99、原始樣本、pool 飽和），不構成生產容量承諾。
- Redis、Blob Storage、進階 Cron 及新的 DB／Broker Adapter 列於 v0.2+，沒有本次時程承諾。

## 升級步驟（tenant-only → organization-enabled）

1. 部署階段以分離的 migrator 角色執行生成專案的 `cmd/migrate`（全域鎖、模組相依序）；API 程序只做 Schema Compatibility Check，不自行遷移。
2. 前向升級會把既有 books 資料回填 `tenant/TenantID` owner、切換成 exact-owner RLS 政策並保留 FORCE 旗標，不猜測 Organization；舊 tenant-only API 對升級後 schema 拒絕啟動。
3. 回滾不提供 Down migration；以向前修復與備份還原為原則。備份須含資料與 schema，RPO／RTO 以實測為準。
4. 詳細演練程序（乾淨重建、升級、備份／還原、負載、安全審查）見[發布演練 runbook](../runbooks/release.md)。
