# 平台設定與 CLI API 變更

Framework 版本維持 0.1.0。新增 platform/cache、platform/settings、platform/features 及 cmd/pangolin；現有 UOW、Tenant、Scope、Events 的公開契約不放寬。完成狀態由 M5 同版 Gate 與里程碑規劃書維護。

Cache key 由可信 context 衍生完整 owner；Private 資料另含 principal／authority revision。Memory 有界容量、TTL、載入合併、獨立等待取消、失效事件與固定維度計數。需要跨程序可靠通知時注入 Publisher／Outbox；本機 Memory 不提供跨程序共享或 DB 原子交易。

Settings Definition 明示可繼承 key、Default 與型別驗證；Provider.Read 回傳同一原子 snapshot 的候選值與版本，任何有效更新都必須更新版本。即使命中 Cache 仍核對來源版本，通知失敗不服務未核對的舊資料。MemoryProvider 是組裝管理 Port，沒有跨程序持久化。Update 先驗 settings.write，僅修改目前 Scope；保存後通知失敗會同時回傳新版本與錯誤，不能視為 rollback 後盲目重試。

Organization Store 新增 Parent 中立 ancestry Port：已 admission 的 UOW 保持簽署快照；其他讀取重新查驗當前權威。一般設定不授權跨 Scope 內容。Features 先驗 Permission，再依 ScopeKinds／Settings／明示 Ceiling 評估 Boolean、Quota、Enum；安全／配額上限只收緊。Enum 上限依明示由低至高的選項順序。

CLI new 預設 tenant-only；--with organization 同時生成完整 Enterprise／Organization、migrations／control plane 與 Scope-aware schema，不提供半套開關。既有應用不能只改 pangolin.json 切換 Profile；須遵循原前向 owner migration／Provider 移除契約。每個生成物包含固定 0.1.0 Runtime 原始碼及 checksum manifest，本機 replace 可在首次正式 tag 前使用；發行後改用等價版本依賴是明示升級動作。

module add 更新編譯期 registry 並建立 README；migrate create 產生全專案唯一序號，SQL 需由開發者完成後才部署。migrate status 只讀 Goose ledger；真正 migration 由生成專案的 cmd/migrate 持有全域鎖執行。doctor 查工具／runtime checksum；generate openapi 提供 Profile 專屬 OpenAPI 3.1，保護已修改的文件。命令錯誤非零退出，new／重複 module／migration 不覆寫既有檔案。

生成範本提供可讀寫 API、必要 Audit、可靠 Outbox 保存及冪等成功結果；外送 Broker Worker 是獨立組裝工作，不宣稱未啟用 Worker 時已完成外部配送。範本使用明確 local IdP 與 seed，正式部署需替換身分來源及 Secrets。

補正 JSON Configuration 與 Settings 的 ABP 分工：Configuration 層負責 colon/index flatmap，Settings 只查 Settings:+完整名稱。既有 RawMessage API 透過明示 converter 接 typed Feature，沒有自動 JSON 猜型別。包含 .NET 10 的 null／空物件／空陣列、大小寫與 duplicate/collision 例外；真實 JSON 到 Resolve／快取／更新及完整 Scope 繼承均為必跑回歸。
