# Jobs 與運維 API 變更

Framework 產品版本維持 0.1.0。新增 `platform/jobs`、`platform/jobs/postgres` 與 `observability`；現有 UOW 與事件交易／Scope／Commit Unknown 契約保持不變。正式完成狀態依同版 Gate 與里程碑規劃書。

Jobs 部署需先合併 `platform/jobs/postgres.Migrations`，並用新 Registry／Worker 明示完整容量、lease、timeout 與重試／retention。Job ID 是至少一次處理的穩定冪等鍵；不要將外部副作用包裝成 exactly-once。管理取消／重送必須在目前 owner 的授權 UOW 與必要 Audit 內完成。

事件容量組裝改用 `events/postgres.NewBoundedStore`，部署時另合併 `CapacityMigrations`。舊 `NewStore` 保留既有 API 相容性；新組裝應使用明示容量的建構式。事件容量超限回 429／EVENT_CAPACITY_EXCEEDED，Jobs 回 429／JOB_CAPACITY_EXCEEDED，應保留同操作 key 並有界退避；不跳過業務 UOW。

Envelope 加入可省略 `TraceParent`／wire `traceparent`，舊格式解碼及無欄位序列化仍相容，不修改已發布 payload schema。外部簽章／完整 fingerprint 包含目前實際完整 wire；重送使用持久化 bytes，不重新生成 owner 或追蹤欄位。

OpenTelemetry 採明確 Provider／context 注入，應用自行設定 SDK sampling、exporter、保留與有界 Shutdown；不建立全域 Provider。Telemetry 不記錄 SQL／payload／token／錯誤原文，Metrics 不包含 owner ID。`Health` 的必要依賴由程序明示，可選 Broker 不直接停用純 API readiness。

舊的 M1 Bookstore 薄流程保留作累積回歸與範例；新的可靠佇列組裝使用公開 Jobs／Events Port。完整恢復、滿額與停機順序見 [操作手冊](../runbooks/operations.md)。
