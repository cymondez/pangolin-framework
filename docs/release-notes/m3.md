# 0.1.0 開發版：安全與可靠事件 API／Schema 變更

版本仍為 0.1.0。本文件說明目前變更，正式完成狀態以里程碑與同版驗收證據為準。

新增 `tenancy`／PostgreSQL Tenant 投影、`security/policy`、Scope selector／admission／inventory、`application.AuthorizedCommand`、HTTP Pipeline、必要 Audit、Local／Outbox／Inbox 與 Serializer Registry。舊 ScopeBinding 仍是值，呼叫端不能自行構造一個值來取得可信 context。

Runtime Options 增加 `StartupChecks`。外部 positional literal 請改成 `runtime.Options{DrainTimeout: ..., CleanupTimeout: ...}`，並在持久化應用組裝中註冊 Schema Compatibility 與完整 Scope Inventory；檢查成功後才會 Start。Provider 的直接 Authorize 呼叫也需使用目前 context 的相同 binding。

Organization 提供完整治理 Store、HTTP Adapter、受稽核加入 owner／復原、版本化資料匯出／匯入與替換對帳。Tenant 身分投影與一般業務 owner Catalog 分離，不將 IdP Org claims 當權威。治理事件沿用發起 UOW 的 ScopeRef，受影響 target 放在 payload。

部署使用 Goose v3.30.0 與既定全域鎖，API 不自行遷移。tenant-only 不安裝組織 migration。既有 Bookstore 的 scope 升級檔會明確回填 tenant owner、同交易移除全部舊 permissive policies、安裝精確 owner RLS，最後改為既有 ScopedRepository 使用的 `scope_books`；舊 tenant-only API 的相容性 probe 因而拒絕啟動。切換前 Drain 並備份，改以 scope-aware Repository 與可靠 Publisher 組裝；不要把 M1 的範例 Replicator 當完整可靠 Worker。

可靠事件 wire 保留 snake_case 與完整 ScopeRef，無上游原因的 causation_id 可為 null。舊 tenant-only 信封只允許透過明示註冊的 LegacyTenant schema 補為 tenant scope，Org 事件不能降級。已發布 type／version 的 payload 仍受 Registry 驗證。

必要 Audit／成功結果與業務同交易；外部副作用仍需 Provider 冪等鍵或二次 Outbox。Job 共用 Scope execution 契約已可組裝，完整持久化 Job Worker、容量與觀測仍依後續範圍交付。

Ownerless 是持久停用狀態；本地 Tenant 投影撤權的 optional hook 同步 Catalog／私有 revision，復權不自動恢復 scope。替換部署須保留此 hook；正常 Resume／Enterprise JoinAsOwner 不能取代有稽核的 Recover。
