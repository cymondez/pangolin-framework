上一個範例我們直接在 `Start` 裡寫死 `fmt.Println("Hello, panGOlin!")`。真實專案中，業務邏輯會抽成獨立的 **Service**，而環境差異（名稱、連線位址、逾時）會抽成 **Configuration**。這個教學帶你把這兩塊自然接上 panGOlin 模組。

---

## 你將學到的三個核心因果

1. **為什麼要在 `Configure` 註冊服務，而不是在 `Start` 裡直接 `NewGreetingService()`？**
   把服務交給 DI 容器管理後，Runtime 就能自動解析建構子相依、控管存活期間（Singleton／Transient／Operation）、統一在停機時執行資源清理，而且測試或擴充時能明確替換實作。
2. **為什麼同模組內的 `GreetingService` 不需要先寫介面（Interface）？**
   在 Go 裡過度提前抽介面只會增加樣板碼。panGOlin 允許在同模組內直接以具象型別 `*GreetingService` 註冊與解析；**只有當其他模組需要呼叫你時**，才把介面抽到獨立的 `contracts` 套件並 `Export`（詳見[依賴注入](../fundamentals/dependency-injection.mdx)）。
3. **設定優先序如何運作？**
   ```text
   低優先 ──────────────────────────────────────────────────────▶ 高優先
   內建與模組預設 (SetDefault)  <  設定檔 (file)  <  環境變數 (environment)  <  命令列參數 (cli)
   ```
   右邊來源自動覆寫左邊。這讓模組作者只需提供安全的本機預設值，維運人員部署時用環境變數覆寫即可，完全不用改程式。

### 逐段導讀：看懂 `Configure` 與 `Start` 的分工

1. **`b.SetDefault("app.name", "World")`**（在 `Configure` 內）
   - 由模組自己宣告它需要的設定鍵與預設值。如果多個模組不小心對同一個鍵宣告衝突預設，啟動前就會報錯，不會默默互蓋。
2. **`module.AddSingleton(b.Services(), NewGreetingService)`**（在 `Configure` 內）
   - 透過高階泛型輔助函式註冊建構子，解析鍵就是建構子的精確回傳型別 `*GreetingService`。
   - `AddSingleton` 代表整個應用只建立一次並共用；若每次取得都要新實例改用 `module.AddTransient`，若每次請求／操作隔離則用 `module.AddOperation`（皆可搭配 `module.As(contract)` 貢獻介面實作）。
3. **`rt.Config().Lookup("app.name")`**（在 `Start` 內）
   - 到了 `Start` 階段，所有設定層已經合併且驗證完成並轉成只讀，直接查詢就會拿到最終生效的值。
4. **`module.Resolve[*GreetingService](ctx, rt.Services())`**（在 `Start` 內）
   - 使用型別安全的泛型 `Resolve[T]` 取得服務，編譯期就能檢查型別，不需要手動做 `value.(*GreetingService)` 斷言。
5. **`app.Sources(config.Source{Name: "environment", Values: env})`**（在 `main` 內）
   - panGOlin 不會偷偷掃描整台主機的所有環境變數。由應用入口明確決定「哪一個環境變數對應到哪一個設定鍵」，避免敏感變數或拼錯名稱造成非預期覆寫。

## 2. 執行並實測環境變數覆寫

在 **`hello-pangolin`** 資料夾先執行預設版本：

```bash
go run .
```

預期輸出（使用模組預設值 `"World"`）：

```text
Hello, World!
```

接著注入環境變數 `APP_NAME=Reader` 覆寫預設值，再次執行：

**Windows PowerShell：**

```powershell
$env:APP_NAME = 'Reader'
go run .
Remove-Item Env:APP_NAME
```

**macOS／Linux：**

```bash
APP_NAME=Reader go run .
```

這次應該看到：

```text
Hello, Reader!
```

> **提示**：你也可以直接從框架原始碼的 `examples/basics` 資料夾執行 `go run ./root-greeting`，看到完全相同的結果。

## 新手常見錯誤提醒

- **不要把 `b.Services()` 存成 struct 欄位留到 `Start` 再註冊**：`Configure` 結束後註冊權限會立即撤銷（Revoke），事後呼叫會被框架拒絕，確保服務圖在啟動前就完全定型。
- **不要在 `Configure` 裡試圖解析服務**：此時其他模組可能還沒註冊完畢；所有解析與實際業務執行都應放在 `Start` 或後續請求處理中。
