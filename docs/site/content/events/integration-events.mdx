當書籍建立成功後，你可能想更新查詢資料、寄通知或交給另一個服務處理。Integration Event 是用來描述這種已發生變更的訊息。

```bash

```

## 事件欄位怎麼填？

| 欄位 | 你的應用應提供的資料 |
|---|---|
| ID | 同一個事件的穩定識別，重送時保留原值 |
| Type／SchemaVersion | 事件型別與 payload 結構版本 |
| TenantID／ScopeKind／ScopeID | 這次可信操作的資源擁有範圍 |
| OccurredAt | 事件發生時間 |
| CorrelationID／CausationID | 用來追查請求與原因的識別 |
| Producer／Payload | 生產模組與 JSON 資料 |

範例使用固定值幫助閱讀；實際請求的 Tenant／Scope 來自[驗證後的 context](../security/multi-tenancy.md)。事件中的欄位本身不會授予權限。

## 如何避免資料已保存，事件卻遺失？

使用 Outbox：在同一筆業務交易保存資料與待送事件。交易提交後，由 Worker 將事件送到 Broker。Consumer 再使用 Inbox 記錄處理過的 EventID，避免重送導致重複效果。

Bookstore 已示範這條完整流程，請依[教學](../tutorials/bookstore.md)同時啟動 API 與 Worker。Broker 的 publish ACK 代表訊息已被接受，並不代表接收端的業務已完成。

## 使用 NATS Adapter

`events/nats` 的 Connect 建立連線，Provision 明確建立串流，Send 等待 JetStream 的可靠確認。Subscribe／Next 接收事件，業務與 Inbox 持久化完成後才 Ack。

Bookstore 教學的環境準備會建立自己的 `BOOKSTORE_DEMO` 串流。自行組裝時要讓 stream／subject／consumer 配置一致，並保留連線的唯一清理擁有者。連線中斷時目前由程序重啟恢復，不會自動重跑你的業務 callback。
