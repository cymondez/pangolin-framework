## 發現的行為觀察（非缺陷、未改 production）

1. `events/nats` 測試 stream 用 `Provision`（64MiB MaxBytes）會被共用伺服器帳戶 256MiB `max_file_store` 既有 RT_* fixture 串流擠爆（`nats: insufficient storage resources available`）；live 測試改以相同形狀（file storage＋limits retention）但 4MiB 預算自行供應，Production `Provision` 行為未動。若未來測試需要真實 64MiB 環境，需提高 `max_file_store` 或清理既有串流。
2. `Session.WriteDelivery(item, nil)`／關閉後寫入會先回 `REALTIME_INVALID`（write == nil 檢查在 work.Enter 之前），與「關閉後 ErrClosed」的直覺順序不同，屬既有合約，測試依實際順序撰寫。
3. `sendCompletion` 在 channel 可送出但 ctx 已取消時 select 任一 arm 成立（本測試以「channel 滿載＋ctx 取消」強制 ctx-done arm），生產行為符合「不等待」契約。
4. docker compose 環境（pangolin-realtime-example PG 26000／NATS 26001）維持運行未清理（依指示交由主代理處理）；P3-COVERAGE-* 測試 stream 於測試 cleanup 自動刪除，NATS 伺服器僅餘原有 RT_* 串流。
